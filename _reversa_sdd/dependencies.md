## Observations (🟡 inferred)

- **Dual bundler strategy** 🟢: esbuild for the extension (Node target), Vite for the webview (browser target).
- **State management split** 🟢: extension uses VS Code workspaceState; webview uses Zustand stores (`cloud-agent-store`, `devin-store`, `spec-explorer-store`).
- **`ts-loader` + `copy-webpack-plugin`** present as devDeps 🟡 — possible legacy webpack path superseded by esbuild/Vite; the Archaeologist should confirm whether they are still wired into any build.
- **Markdown rendering stack** is duplicated across extension and webview 🟢 (`markdown-it` + mermaid + plantuml on both sides), consistent with rendering specs/previews in both contexts.
- **No HTTP server / database / message-broker dependencies** 🟢 — all integration is via the VS Code API, the ACP SDK (subprocess), and cloud provider HTTP APIs (Devin, GitHub Copilot) reached through their own clients in `src/features/`.
