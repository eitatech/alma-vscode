## 2. Dual-keyed message protocol 🟡

> `index.tsx:30,54`; `types.ts:389-503`. Every message carries both `type` ("hooks/x") and an optional `command` ("hooks.x"); the webview sends `command = type.replace(/\//g, ".")` and reads `payload.type ?? payload.command`, `payload.payload ?? payload.data`.

```mermaid
flowchart LR
    subgraph Out [webview -> host]
      O1[type: hooks/create] --> O2[+ command: hooks.create] --> O3[vscode.postMessage]
    end
    subgraph In [host -> webview]
      I1[hooks/sync OR hooks.sync] --> I2[messageType = type ?? command]
      I2 --> I3[body = payload ?? data]
      I3 --> I4[switch on both spellings]
    end
```

## 4. MCP tool-name parsing algorithm 🟢

> `lib/mcp-utils.ts:40-82` — server IDs never contain `_`; may contain `.` (domain) or `/` (path).

```mermaid
flowchart TD
    A[extractServerIdFromToolName toolName] --> B{starts with &quot;mcp_&quot;?}
    B -- no --> B0[return toolName.toLowerCase fallback]
    B -- yes --> C[strip &quot;mcp_&quot; prefix]
    C --> D{contains / or . ?}
    D -- yes --> E[pathEnd = max lastIndexOf '/' , '.']
    E --> F[underscore after pathEnd -> server id boundary]
    D -- no --> G[first '_' index]
    G --> H{found?}
    H -- no --> H0[whole string = server id]
    H -- yes --> I[substring before first '_']
    F --> Z[lowercase server id]
    H0 --> Z
    I --> Z
```
