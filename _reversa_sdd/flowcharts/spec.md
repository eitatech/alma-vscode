## 2. Send-to-review gating 🟢

```mermaid
flowchart TD
    A([canSendToReview specId]) --> B{spec found?}
    B -- no --> R0[blocker: Spec not found]
    B -- yes --> C{status normalized}
    C -- review --> R1[blocker: already in review]
    C -- not current/reopened --> R2[blocker: not in current status]
    C -- current/reopened --> D{pendingTasks > 0?}
    D -- yes --> R3[blocker: N pending tasks]
    D -- no --> E{pendingChecklistItems > 0?}
    E -- yes --> R4[blocker: N pending checklist items]
    E -- no --> F[canSend = true]
    F --> G[sendToReview -> updateSpecStatus review]
    R0 & R1 & R2 & R3 & R4 --> H[canSend = false, return blockers]
```

## 3. Change-request lifecycle + auto-return 🟢

```mermaid
stateDiagram-v2

    open --> inProgress: attachTasksToChangeRequest (sentToTasksAt set)
    open --> blocked
    inProgress --> addressed: all tasks done (archivalBlocker=false)
    addressed --> inProgress: a done task reverted (archivalBlocker=true)
    addressed --> [*]
    note right of addressed
      When all CRs addressed AND all tasks done
      AND zero pending tasks/checklist ->
      shouldReturnToReview -> returnSpecToReview.
    end note
```
